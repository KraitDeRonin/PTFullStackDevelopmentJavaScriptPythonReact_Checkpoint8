1. Los dos conceptos fundamentales: Clases y Objetos

[Programación orientada a objetos]

Para un principiante, la mejor analogía es la de una fábrica de coches:

  • La Clase (El Molde): Es el plano o diseño. No es un coche real, sino las instrucciones de cómo debe ser un coche (tiene 4 ruedas, un motor, un color).
  • El Objeto (El Producto): Es el coche real que sale de la fábrica. Puedes crear un coche rojo, uno azul o uno deportivo usando el mismo molde.

Sintaxis en JavaScript

// Se define la Clase (El molde)
class Coche {
    constructor(marca, color) {
        this.marca = marca; // Propiedad
        this.color = color; // Propiedad
    }

    // Método (Acción que el objeto puede hacer)
    arrancar() {
        console.log("El " + this.marca + " está arrancando...");
    }
}

// Se crean Objetos (Instancias)
const miCoche = new Coche("Toyota", "Rojo");
const cocheDeAlex = new Coche("Tesla", "Negro");

miCoche.arrancar(); // "El Toyota está arrancando..."

2. Los 4 Pilares de la POO

Para que un sistema sea verdaderamente orientado a objetos, debe cumplir estos cuatro principios:

A. Abstracción: Simplificar un objeto complejo quedándote solo con lo que importa (ej: usar el volante sin saber cómo funciona el motor).
B. Encapsulamiento: "Esconder" los datos internos para proteger la integridad del objeto de cambios externos accidentales.
C. Herencia: Crear clases nuevas basadas en otras ya existentes (ej: un Coche hereda de Vehiculo).
D. Polimorfismo: Capacidad de que diferentes objetos respondan a la misma orden de formas distintas.

3. El Aparte Técnico: La Jerarquía (El "Es-Un")

La Jerarquía es la estructura que organiza el código de lo más general a lo más específico. En programación, esto se conoce como la relación "Es-Un" (Is-A).

Ejemplo: Un Jedi es un UsuarioDeLaFuerza; un MaestroJedi es un Jedi.

Visualizando la Jerarquía en el Código (RPG)

// Lo más general (Superior)
class Personaje {
    constructor(nombre) {
        this.nombre = nombre;
        this.vida = 100;
    }
}

// Especialización (Intermedio)
class Guerrero extends Personaje {
    atacar() {
        console.log(`${this.nombre} ataca con su espada.`);
    }
}

// Específico (Base)
class CaballeroDeLaMesaRedonda extends Guerrero {
    usarEscudo() {
        console.log(`${this.nombre} bloquea el ataque.`);
    }
}

const arthur = new CaballeroDeLaMesaRedonda("Arturo");

💡 ¿Por qué es vital la Jerarquía?

Mantenimiento: Si añades una propiedad en la clase raíz (Personaje), toda la jerarquía la hereda automáticamente.

Advertencia: No abuses de la jerarquía. Un árbol muy profundo puede volverse frágil. En 2026, la tendencia es favorecer jerarquías planas.

4. Riesgos y Consideraciones

  • Sobre-ingeniería: No crees clases para problemas extremadamente simples.
  • Curva de aprendizaje: Requiere un cambio de mentalidad para entender cómo se comunican los objetos.

Diccionario de Términos (Glosario)

  • Clase: El plano o plantilla desde la cual se crean los objetos.
  • Objeto: Una instancia única de una clase que contiene datos y funcionalidades.
  • Instancia: El proceso de crear un objeto concreto a partir de una clase usando la palabra new.
  • Método: Una función definida dentro de una clase que describe una acción que el objeto puede realizar.
  • Herencia: Mecanismo por el cual una clase (hija) adquiere las propiedades y métodos de otra (padre).
  • this: Palabra clave que hace referencia al objeto actual que está ejecutando el código.
