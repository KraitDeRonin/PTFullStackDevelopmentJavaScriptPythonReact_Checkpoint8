¿Qué es una promesa en JS?

Checkpoint 8 - Asincronía y Gestión de Tareas

← Volver al inicio

Introducción

En términos técnicos, una Promesa es un objeto que representa el éxito o el fracaso de una operación asíncrona.

¿Para qué se utiliza?
Se utiliza para gestionar tareas que toman tiempo y que no se sabe exactamente cuándo terminarán. Por ejemplo:

  • Pedir datos a una base de datos.
  • Descargar una imagen de internet.
  • Leer un archivo muy pesado.

Sin las promesas, JavaScript se quedaría "congelado" esperando. Gracias a ellas, el motor de JS puede seguir con otras tareas mientras la operación se completa en segundo plano.

1. Los 3 estados de una Promesa

[Diagrama: Flujo de una promesa]

Para entender una promesa, piensa en cuando pides comida en un restaurante:

  • Pending (Pendiente): El pedido está hecho. La comida se está cocinando. Aún no se sabe el resultado final.
  • Fulfilled (Resuelta / Cumplida): ¡Éxito! La comida llegó a la mesa. Ya puedes ejecutar el siguiente código.
  • Rejected (Rechazada): Hubo un problema (no había stock). Hay que decidir cómo gestionar el error.

2. Sintaxis y Ejemplo Práctico

Cómo se crea una promesa

const miPedido = new Promise((resolve, reject) => {
    const hayComida = true;

    if (hayComida) {
        resolve("¡Aquí tienes tu hamburguesa! 🍔");
    } else {
        reject("Lo siento, no quedan ingredientes. ❌");
    }
});

Cómo se consume (se usa) una promesa

Utilizamos los métodos .then() para el éxito y .catch() para los errores.

miPedido
    .then((mensaje) => {
        // Éxito (resolve)
        console.log(mensaje);
    })
    .catch((error) => {
        // Error (reject)
        console.error(error);
    })
    .finally(() => {
        // Se ejecuta SIEMPRE al final
        console.log("Proceso terminado.");
    });

3. ¿Por qué son mejores que los antiguos "Callbacks"?

Antes de las promesas, se usaban funciones llamadas "callbacks". Cuando había muchas tareas seguidas, el código se volvía una maraña ilegible llamada Callback Hell (El infierno de los callbacks).

Las promesas permiten encadenar tareas de forma vertical y limpia: 

hacerPedido()
    .then(comer)
    .then(pagar)
    .catch(reclamar);

⚠️ Riesgos y Errores Comunes

Olvidar el .catch(): Si una promesa se rechaza y no tienes un .catch(), el programa puede lanzar una excepción no controlada.

Promesas "eternas": Si olvidas llamar a resolve o reject dentro del ejecutor, la promesa se quedará en estado Pending para siempre, consumiendo memoria.

Diccionario de Términos (Glosario)

  • Asincronía: Capacidad de un programa para iniciar una tarea y seguir con otras mientras espera que la primera termine.
  • Objeto Promise: Un contenedor para un valor que puede estar disponible ahora, en el futuro o nunca.
  • Callback Hell: Problema de legibilidad causado por múltiples funciones anidadas una dentro de otra.
  • Resolve: Función que se llama cuando la tarea asíncrona termina con éxito.
  • Reject: Función que se llama cuando ocurre un error en la tarea asíncrona.
  • Settled: Estado de una promesa cuando ya no está pendiente (ya ha sido resuelta o rechazada).
